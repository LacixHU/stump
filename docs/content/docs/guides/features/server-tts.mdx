title: Server TTS (Piper, Supertonic)
description: Optional server-side text-to-speech for read aloud, limited to selected users
---

Server TTS synthesizes speech on the Stump host for the **Read aloud** feature. Browser/OS voices remain the default for everyone else.

Two neural engines are built into the Stump server. Install voices for either or both:

- **[Supertonic 3](https://huggingface.co/supertone-oss-archive/supertonic-3)** — more natural speech in 31 languages from one model (about 400 MB), 10 voice styles (`F1`–`F5`, `M1`–`M5`) shared by every language. It reads text directly, so it does not use espeak-ng.
- **[Piper](https://github.com/rhasspy/piper)** — small, very fast voices, one file per voice, in more languages (for example Norwegian, which Supertonic lacks). Piper turns text into phonemes with espeak-ng.

No separate executable or library is needed: ONNX Runtime and espeak-ng are compiled into the server binary. espeak-ng only reads its data from files, so the server unpacks it (about 20 MB) into `{config_dir}/espeak-ng` the first time a Piper voice is used.

## Requirements

1. Put voices into a `voices` folder next to the server binary:
   - **Supertonic**: download the model into a subfolder (any name without `:`; it becomes part of the voice ids):
     ```sh
     hf download supertone-oss-archive/supertonic-3 \
       --revision aafc6e32416a594460b32413efc49d7fe4ce6d46 \
       --include "onnx/*" "voice_styles/*" "LICENSE" \
       --local-dir voices/supertonic-3
     ```
   - **Piper**: one or more voice models (`.onnx` + matching `.onnx.json`) directly in the folder.
2. Grant the **Server TTS** permission only to users who should use it.

A Windows install with both looks like:

```text
stump_server.exe
voices/
  hu_HU-anna-medium.onnx
  hu_HU-anna-medium.onnx.json
  supertonic-3/
    onnx/
      tts.json, unicode_indexer.json, duration_predictor.onnx,
      text_encoder.onnx, vector_estimator.onnx, vocoder.onnx
    voice_styles/
      F1.json … M5.json
```

## Voices

Piper voice ids are the file names without `.onnx`, such as `hu_HU-anna-medium`.

Supertonic voice ids are `<folder>:<language>:<style>`, such as `supertonic-3:hu:F1`, and appear in the voice list as _Supertonic 3 Hungarian F1_. The model speaks every language with every style, so the list shows only the languages you choose with `supertonic_languages`. By default it shows English plus the languages of your installed Piper voices.

Supertonic languages: Arabic, Bulgarian, Croatian, Czech, Danish, Dutch, English, Estonian, Finnish, French, German, Greek, Hindi, Hungarian, Indonesian, Italian, Japanese, Korean, Latvian, Lithuanian, Polish, Portuguese, Romanian, Russian, Slovak, Slovenian, Spanish, Swedish, Turkish, Ukrainian and Vietnamese (`ar bg hr cs da nl en et fi fr de el hi hu id it ja ko lv lt pl pt ro ru sk sl es sv tr uk vi`).

## Configuration

| Setting                | Env                          | Default                                 | Description                                                      |
| ---------------------- | ---------------------------- | --------------------------------------- | ---------------------------------------------------------------- |
| `piper_voices_dir`     | `STUMP_PIPER_VOICES_DIR`     | `voices` next to the server binary      | Directory of Piper voices and Supertonic model folders           |
| `piper_default_voice`  | `STUMP_PIPER_DEFAULT_VOICE`  | first voice listed                      | Default voice id (Piper or Supertonic)                           |
| `supertonic_languages` | `STUMP_SUPERTONIC_LANGUAGES` | English + languages of the Piper voices | Supertonic languages to list: comma-separated codes, or `all`    |
| `supertonic_steps`     | `STUMP_SUPERTONIC_STEPS`     | `8`                                     | Supertonic denoising steps: fewer is faster, more sounds cleaner |
| `server_tts_max_chars` | `STUMP_SERVER_TTS_MAX_CHARS` | `2000`                                  | Max characters per synthesize request                            |

Example `Stump.toml`:

```toml
# piper_voices_dir = "/var/lib/stump/voices"
piper_default_voice = "supertonic-3:hu:F1"
supertonic_languages = "hu,en"
# supertonic_steps = 8
```

There is no on/off switch: server TTS is available whenever voices are present. The former `piper_path`, `enable_server_tts`, `espeak_ng_path` and `espeak_ng_data_dir` settings are no longer used.

On Windows, the config directory path must contain only ASCII characters, because espeak-ng opens its data files with narrow-character APIs. Set `STUMP_CONFIG_DIR` if your user profile path has accented characters.

## Performance

Piper voices are loaded on first use and kept in memory (up to four at a time). Replacing a voice file on disk reloads it automatically.

The Supertonic model is loaded on first use and kept in memory (about 400 MB). It is slower than Piper. On a 16-core desktop CPU, with the default 8 steps, a sentence takes about a sixth to a third of its spoken length to generate, which read aloud hides by preparing the next sentence while the current one plays. On slower hosts, lower `supertonic_steps` (5 is about twice as fast) at some cost in clarity.

## Building

espeak-ng is a git submodule at `crates/piper_tts/espeak-ng`. Check it out before building:

```sh
git submodule update --init crates/piper_tts/espeak-ng
```

The build needs a C compiler (MSVC on Windows, gcc or clang elsewhere) and compiles espeak-ng's phoneme data and dictionaries for all its languages; this takes a few minutes the first time and is cached afterwards.

To test a Supertonic model without the server:

```sh
echo "Jó reggelt kívánok." | cargo run --release -p supertonic_tts --example supertonic_speak -- voices/supertonic-3 F1 hu out.wav
```

## Permissions

Server TTS is available only when:

1. At least one usable voice is installed: a Supertonic model folder, or a Piper voice (`.onnx` with its `.onnx.json`) whose built-in espeak-ng data could be unpacked (otherwise a warning is logged and Piper voices are hidden)
2. The user has the **Server TTS** permission (`ACCESS_SERVER_TTS`), or is the server owner

Assign the permission under **Settings → Users**. Users without it only see browser read aloud.

## Using it

In the reader, open read aloud settings. If server TTS is available for your account, an **Engine** selector appears:

- **Browser** — device/OS voices (Web Speech API)
- **Server** — neural synthesis on the Stump host, with the voices installed there

Speech is generated per sentence and streamed as WAV audio. The reader keeps paragraph and line breaks (newlines become sentence boundaries) and prefetches the next sentence so playback stays continuous. Concurrent jobs are limited on the server to protect CPU.

Hungarian voices (Piper `hu_*` voices and Supertonic voices with language `hu`) rewrite common English names and clearly foreign words to Hungarian phonetics before speaking them. That is a pronunciation aid, not a translator.

## API

Authenticated endpoints (permission required):

- `GET /api/v2/tts` — status, default voice, available voices
- `POST /api/v2/tts/speak` — `{ "text": "...", "voice": "optional-id", "rate": 1.0 }` → `audio/wav`
