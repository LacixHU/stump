---
title: Server TTS (Piper)
description: Optional server-side text-to-speech for EPUB read aloud, limited to selected users
---

Server TTS uses [Piper](https://github.com/rhasspy/piper) neural voices on the Stump host to synthesize speech for the EPUB **Read aloud** feature. Browser/OS voices remain the default for everyone else.

The Piper engine is built into the Stump server: no separate `piper` executable, espeak-ng library or data folder is needed. ONNX Runtime and espeak-ng (used to turn text into phonemes) are compiled into the server binary. espeak-ng only reads its data from files, so the server unpacks it (about 20 MB) into `{config_dir}/espeak-ng` the first time speech is requested.

## Requirements

1. Download one or more Piper voice models (`.onnx` + matching `.onnx.json`) into a `voices` folder next to the server binary.
2. Grant the **Server TTS** permission only to users who should use it.

A Windows install looks like:

```text
stump_server.exe
voices/
  en_US-lessac-medium.onnx
  en_US-lessac-medium.onnx.json
```

## Configuration

| Setting                | Env                          | Default                            | Description                           |
| ---------------------- | ---------------------------- | ---------------------------------- | ------------------------------------- |
| `piper_voices_dir`     | `STUMP_PIPER_VOICES_DIR`     | `voices` next to the server binary | Directory of `.onnx` voice models     |
| `piper_default_voice`  | `STUMP_PIPER_DEFAULT_VOICE`  | first voice found                  | Voice id (filename without `.onnx`)   |
| `server_tts_max_chars` | `STUMP_SERVER_TTS_MAX_CHARS` | `2000`                             | Max characters per synthesize request |

Example `Stump.toml`:

```toml
# piper_voices_dir = "/var/lib/stump/voices"
# piper_default_voice = "en_US-lessac-medium"
```

There is no on/off switch: server TTS is available whenever voices are present. The former `piper_path`, `enable_server_tts`, `espeak_ng_path` and `espeak_ng_data_dir` settings are no longer used.

On Windows, the config directory path must contain only ASCII characters, because espeak-ng opens its data files with narrow-character APIs. Set `STUMP_CONFIG_DIR` if your user profile path has accented characters.

Voices are loaded on first use and kept in memory (up to four at a time), so only the first sentence spoken with a voice pays the model load time. Replacing a voice file on disk reloads it automatically.

## Building

espeak-ng is a git submodule at `crates/piper_tts/espeak-ng`. Check it out before building:

```sh
git submodule update --init crates/piper_tts/espeak-ng
```

The build needs a C compiler (MSVC on Windows, gcc or clang elsewhere) and compiles espeak-ng's phoneme data and dictionaries for all its languages; this takes a few minutes the first time and is cached afterwards.

## Permissions

Server TTS is available only when:

1. At least one valid voice model (`.onnx` with its `.onnx.json`) is present
2. The built-in espeak-ng data can be unpacked (otherwise a warning is logged and the feature reports as unavailable)
3. The user has the **Server TTS** permission (`ACCESS_SERVER_TTS`), or is the server owner

Assign the permission under **Settings → Users**. Users without it only see browser read aloud.

## Using it

In the EPUB reader, open read aloud settings. If server TTS is available for your account, an **Engine** selector appears:

- **Browser** — device/OS voices (Web Speech API)
- **Server (Piper)** — neural synthesis on the Stump host

Speech is generated per sentence and streamed as WAV audio. The reader keeps paragraph and line breaks (newlines become sentence boundaries) and prefetches the next sentence so playback stays continuous. Concurrent jobs are limited on the server to protect CPU.

Hungarian voices (`hu_*`) rewrite common English names and clearly foreign words to Hungarian phonetics before Piper speaks them. That is a pronunciation aid, not a translator.

## API

Authenticated endpoints (permission required):

- `GET /api/v2/tts` — status, default voice, available voices
- `POST /api/v2/tts/speak` — `{ "text": "...", "voice": "optional-id", "rate": 1.0 }` → `audio/wav`
